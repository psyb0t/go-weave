# go-weave

Unofficial Go client for the W&B Weave trace server API, generated with oapi-codegen. If you only want to use the client from an agent, read [.agents/skills/go-weave/SKILL.md](.agents/skills/go-weave/SKILL.md) instead; this file is about changing the repo.

## Architecture

The client is generated end to end. `gen.go` holds the `//go:generate` steps that `make generate` runs:

Spec fetch (`scripts/fetch-spec.sh`) → spec patch (`scripts/patch-spec.sh`) → oapi-codegen with `config.types.yaml` → `types.gen.go`, then oapi-codegen with `config.yaml` → `client.gen.go`.

- `scripts/fetch-spec.sh` downloads the spec the trace server publishes at `https://trace.wandb.ai/openapi.json` to `api/openapi.json` and checks with jq that it is an OpenAPI 3.x document.
- `scripts/patch-spec.sh` writes `api/openapi.patched.json`. Its one patch declares `application/jsonl` for `POST /calls/stream_query`, which the spec lists as `application/json`; without it the generated client tries to decode the JSONL stream as one JSON value and fails. The script fails when the spec no longer has that declaration, so a stale patch gets noticed.
- The spec is OpenAPI 3.1 and oapi-codegen reads it otherwise as is.
- The output is split in two files because a single one would be about 850 KB.

## Stack

- Go 1.26.10, one package `weave` at the module root.
- `github.com/oapi-codegen/runtime` at runtime; oapi-codegen and golangci-lint as `go tool` dependencies.
- No logging: it is a library.

## Layout

- `gen.go`: package doc and the generate steps.
- `config.yaml`, `config.types.yaml`: oapi-codegen configs for the client and the models.
- `client.gen.go`, `types.gen.go`: generated, committed.
- `client_test.go`, `example_test.go`: tests and the README example.
- `scripts/`: spec fetch and patch, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make generate  # download the spec and regenerate both generated files
make dep       # go mod tidy + go mod vendor
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The two configs must keep the same `output-options` and `compatibility`. If they drift, the client refers to model names that `types.gen.go` spells differently and the package stops compiling.
- `scripts/sec.sh` excludes the semgrep rule for `json.Unmarshal` into `interface{}`. oapi-codegen emits it for the spec's untyped schemas. Do not widen the exclusion.
- Twelve endpoints stream JSONL (`application/jsonl` or `application/x-ndjson`): the two `stream_query` endpoints, `/annotation_queues/query`, `/completions/create_stream` and the v2 list endpoints. Their wrappers have no typed body field.
- CI skips the generate drift check, because `make generate` always pulls the newest upstream spec. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
